---
name: hitreg-dungeon-authoring
description: Build or refine an instanced Blender-to-DC dungeon in HitReg - the shared dungeon pipeline (tools/dungeon-pipeline stages and quality gates), role noise on natural rooms, and rooms from the dungeon room kit (tools/dungeon-room-kit). Use when starting, porting or extending a dungeon; pair with dungeon-build (gates), dungeon-standards (design) and dungeon-lighting.
---

Read `docs/blender-dc-authoring.md` first, then the dungeon's own `authoring/NOTES.md` / plan when present. Reference dungeons on the sample world: `projects/fieldfast-barrow`, `projects/fieldfast-hall`, `projects/gnawspur-deeps`, `projects/rime-hall`.

Every Blender to DC dungeon uses the shared pipeline: its `authoring/pipeline.mjs` imports `tools/dungeon-pipeline/pipeline.mjs` (`standardStages({ id, override })` + `runPipeline`) instead of copying another dungeon's file. That gives the build stages plus the quality gates `noise` (role-noise table embedded, natural rock noised, no prism roofs or box lumps), `originality` (no builder shared with another dungeon), `atlas` (one page; one stone, wood and metal colouring; no hue-shifting tints), `recipe` (per room: built detail, props through dressing plans, bone cap, 2-5 lit fixtures, 6-12 decals from 3+ textures, a set piece) and `compare` (sheet beside fieldfast-barrow and fieldfast-hall); a FAILED gate blocks `--next`. Run them with `node ../../../../tools/dungeon-pipeline/quality.mjs all --build`. The numbers are `tools/dungeon-pipeline/thresholds.json`, the rules docs/world-standards/dungeons.md "Quality recipe" and projects/proving/authoring/reports/dungeon-quality-recipe.md; a justified miss goes in `authoring/quality-exceptions.json` with a `why`.

Role noise is ON by default for natural roles (owner ruling 2026-10-05). Every Blender to DC dungeon tags natural walls and ceilings with `dc_noise` (`rock-wall`, `rock-roof`, `burrow-roof`, natural-space floors `earth-floor`) and keeps `authoring/noise.json` (defaults: docs/world-standards/dungeons.md); built masonry, timber, trim and stair treads stay crisp (`null`). Shape natural rooms with `tools/mesh-dc/shapes_blender.py` (domed `cave_ceiling`, lofted `cave_tunnel`), not flat prisms with box lumps; protect the walk lane and doorways, embed the table in the stamp, decimate noised bakes after the planar merge. Procedure: docs/blender-dc-authoring.md "DC role noise"; shaping-scale findings: projects/noise-lab/NOTES.md.

Build rooms with the room kit (`tools/dungeon-room-kit`, README there). Write one JSON entry per room (outline or x/y, floor, height, style, doorways) in `authoring/rooms.json`; `node tools/dungeon-room-kit/roomkit.mjs all authoring/rooms.json` places pilasters, bases and capitals, dressed arched doorways, ribbed vaults, wall courses from the 9-sliced carved DC library, niches, wainscot, arcades, timber roof bays, or a shaped noised cave with pillars and stalactites, by rule from a style (`barrow-masonry`, `manor-panelled`, `giant-timber`, `warren-gnawed`, `ice-cave`, or a new style JSON), then exports the stamp with doorway and lane noise protection, DC-bakes and audits each room, and prints its built detail as the `recipe` gate counts it. Inside a dungeon's own `build.py`, `blender_build.build_rooms(rooms)` builds the same architecture before the dungeon's own set pieces, which stay its own. Choose a style per dungeon (or override one), never another dungeon's set-piece builder.
